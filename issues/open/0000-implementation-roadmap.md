## 1. プロダクト定義

Rust版の`no_std`・依存ゼロ・Sans I/Oという性質から、MoonBit版では**OS/Node/DOMに依存しない純粋なMP4コンテナコア**を中心に構築する。MoonBitにおける`no_std`というRust用語の同一性は要求せず、ホスト依存を境界で分離する。

最初の成果物は (1) 通常MP4の構造・track/sampleの正しい読取、(2) Native CLI `demux`、(3) ブラウザで動くMP4 Dump、(4) Rust/WASMとMoonBitの差分レポート。次にfMP4のfile/segment読み書き、通常MP4 mux、codec utilities、字幕、WebCodecs demo、gpui.mbt Native Inspectorへ拡張する。

**M1では実際の映像/音声decode・encodeやプレーヤーを作らない。** Sample payloadはraw bytesとoffsetとして扱う。ブラウザでの後続transcodeにはWebCodecsを利用し、MoonBit独自の動画エンコーダーと呼ばない。

## 2. 推奨アーキテクチャと依存方向

```text
[Web File.slice / Native File I/O / generated bytes]
                         |
                  Range Input Adapter
                         |
       +-----------------+------------------+
       |                                    |
  MP4 File Kind Detector               Dump/CLI UI
       |
  Box Header / Box Tree
       |
  moov/trak + stbl + SampleEntry
       |
  SampleTableAccessor
       |
  +--------------------------+---------------------+
  |                          |                     |
Mp4FileDemuxer       Fmp4SegmentDemuxer    Fmp4FileDemuxer
  |                          |                     |
  +------------ canonical track/sample model -------+
                       |               |
                 Browser Lab      gpui.mbt UI
       |
  Mp4FileMuxer / Fmp4SegmentMuxer
       |
  Output offsets + encoded metadata (caller owns payload I/O)

Rust oracle is a *separate executable* that reads the same fixtures.
```

提案パッケージは`src/bytes`、`src/box`、`src/boxes`、`src/bitstream`、`src/demux`、`src/mux`、および`examples/demux`、`examples/fmp4`、`web/`、`native/`、`tools/oracle`、`tests/fixtures`。実際の`moon.pkg`分割は`0002`で循環依存・target制約を検証した上で確定する。

### 変更できないデータ契約

1. `Sample.timestamp`は各trackのtimescale単位の**DTS**。PTSは`DTS + composition_time_offset`。CTTS未設定(`None`)と0は区別する。DTSの全track時系列統合はfloat丸めなしで比較する。
2. `Mp4FileDemuxer` と `Fmp4FileDemuxer` が返すsample `data_offset` は**ファイル絶対位置**。一方 `Fmp4SegmentDemuxer`が返すoffsetは**当該media-segment buffer先頭からの相対位置**。
3. `Mp4FileMuxer.append_sample`の入力offsetは**出力ファイル絶対位置**。`Fmp4SegmentMuxer.create_media_segment_metadata`の入力offsetは**当該mdat payload先頭からの相対位置**。後者の返り値にpayloadは含まれず、callerが連結する。
4. 通常MP4 Demuxerの`RequiredInput`は`position`と`size: Option`相当。上流の`handle_input`は要求された範囲を一度に満たす契約。固定長で分割受信した場合はI/O adapterで結合し、memory limitを超える要求は明示的に拒否する。
5. 初期のmuxerは同一`TrackKind`1トラックまで（映像／音声／字幕各1）。多言語音声/字幕muxを暗黙に支援しない。
6. JSON比較では64bit整数を十進**文字列**で保持。JSの安全整数精度外をNumberへ強制変換しない。
7. 不正入力によるpanic・制限なしのallocation・無限loopを許容しない。parse用limitsとエラーの位置/原因を持つ。正常入力と不完全入力は区別する。

## 4. テスト・互換性判定

| 区分 | 入力/方法 | 判断 |
| --- | --- | --- |
| Unit | 手作りの合法/違法byte列、size境界、box親子関係、sample mapping | Whatが固定した結果／error種別に一致 |
| Upstream fixture | 上流`tests/testdata`の小さなMP4/AAC/Opus/AV1など（帰属確認後） | Rustの固定SHAから再生成したcanonical goldenと一致 |
| Rust differential | 同じfixtureからRust nativeまたはRust/WASMとMoonBitを別プロセスで動かす | Track kind/id、DTS/CTTS、offset/size、codec entry、失敗分類の一致 |
| Interop | Rust mux→MoonBit demux、MoonBit mux→Rust demux | encodeしたsample payload/metadataが完全復元できる |
| Fuzz/PBT | boundary mutation、壊れたbox、random seeds | panic/無限loop/範囲外参照をしない、発見seedを回帰化 |
| Browser E2E | 実ブラウザでFile input→tree/timeline表示→JSON export | 画像とデータの実操作証跡。差分Labは左右独立で実行 |
| Native UI E2E | Linuxを先行、Mac Apple Siliconは別途実機 | UI入力・選択・終了・表示の動作。未実機は未実行 |
| Performance | 同一fixtureとhostでelapsed/read count/retained memory | 数値の採取と回帰比較。未計測の高速化を宣言しない |

検証状態は **PASS / FAIL / UNVERIFIED / NOT_RUN** を独立に記録する。Rust oracle生成失敗やcandidate未起動は「一致」ではない。実行コマンド・commit SHA・OS/arch・fixture checksum・日時を結果に含める。

## 5. 最初のデモ仕様：MP4 Inspector

- 左ペイン: box type/offset/size階層。unknown boxはRAWとして示し、metadataを捏造しない。
- 中央: Video/Audio/Subtitle track、codec string、timescale、duration、sample数。
- 右: sample index、DTS、PTS、keyframe、file offset、sample size、sample entry切替。
- 入力: browser File API、ファイルを外部アップロードしない。Range読取と解析cancelを備える。
- 比較モード: Rust/WASM結果とMoonBit結果を左右並置し、異なるfield pathと値を表示。
- 実演ケース: black-h264-video／beep-aac／black-av1／black-h264-fmp4／非faststart／切断・未知box。

M1では**動画そのものの再生や変換**をUIに表示できなくてもよい。後続の`0029`だけがWebCodecsへ依存し、codec未対応ブラウザは機能を無効化する。
