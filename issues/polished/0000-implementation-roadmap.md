## 概要

`mp4.mbt` は [shiguredo/mp4-rs](https://github.com/shiguredo/mp4-rs) の MoonBit 移植であり、このファイルは 0001–0034 のローカル Markdown イシューの index である。段階（M0–M5）、各段階の完了ゲート、着手順、検証区分、代表リスクを定義する。実装状況を示す文書ではなく計画であり、進捗に応じて更新する。

## 背景

- 固定参照は `shiguredo/mp4-rs@1282b704f44184ec792e1549b5d31e0c4c54dc59`（調査時の `develop` HEAD）。上流との差分は SHA 更新時に評価し、暗黙の latest 追従を禁止する。
- 上流 license は Apache-2.0。移植・再配布時は著作権・帰属と fixture ライセンスを個別に確認する（[0001](./0001-scope-upstream-license.md) / [0004](./0004-oracle-fixtures.md) / [0033](./0033-release-docs.md)）。
- Rust 版の `no_std`・依存ゼロ・Sans I/O という性質から、MoonBit 版では OS/Node/DOM に依存しない純粋な MP4 コンテナコアを中心に構築する。MoonBit における `no_std` という Rust 用語の同一性は要求せず、ホスト依存を境界で分離する。
- 本計画は GitHub Issue 本文ではなく、`issues/` 配下のローカル Markdown イシュー（整備済みのものは `issues/polished/`）として管理する。
- 最初の成果物は (1) 通常 MP4 の構造・track/sample の正しい読取、(2) Native CLI `demux`、(3) ブラウザで動く MP4 Dump、(4) Rust/WASM と MoonBit の差分レポート。次に fMP4 の file/segment 読み書き、通常 MP4 mux、codec utilities、字幕、WebCodecs demo、gpui.mbt Native Inspector へ拡張する。

## 問題

- 2026-10-16 時点の `main` は README のみで、`moon.mod` や package はなく、ライブラリ実装・動作テストは未実施である。
- 範囲・API・検証方法・配布方針が曖昧なまま着手すると、「Rust 互換」の根拠が失われる。特に offset 基準（ファイル絶対位置と segment 相対位置）、64bit 整数と timescale の精度、moov が末尾のファイルの扱いは誤りやすく、後工程ほど修正コストが高い。
- 上流 HEAD は動き続けるため、固定参照と差分手順がなければ上流の変更を candidate 側のバグと誤判定する。

## 目標

- M0–M5 の段階ごとに「実際に動く成果物」と「次工程へ進む gate」が定義されている。
- 各イシューが単独で実装・レビュー・テストでき、この index のリンクから到達できる（1 件 1 PR 相当）。

## 対象外

## 提案する方針

### プロダクト定義

Rust 版の性質を境界分離の指針として引き継ぎ、ネイティブ CLI・ブラウザ・Native UI が同じ canonical な track/sample model を共有する構成にする。

### アーキテクチャと依存方向

```text
[Web File.slice / Native File I/O / generated bytes]
                         |
                  Range Input Adapter
                         |
       +-----------------+------------------+
       |                                    |
  MP4 File Kind Detector               Dump/CLI UI
       |
  Box Header / Box Tree
       |
  moov/trak + stbl + SampleEntry
       |
  SampleTableAccessor
       |
  +--------------------------+---------------------+
  |                          |                     |
Mp4FileDemuxer       Fmp4SegmentDemuxer    Fmp4FileDemuxer
  |                          |                     |
  +------------ canonical track/sample model -------+
                       |               |
                 Browser Lab      gpui.mbt UI
       |
  Mp4FileMuxer / Fmp4SegmentMuxer
       |
  Output offsets + encoded metadata (caller owns payload I/O)

Rust oracle is a *separate executable* that reads the same fixtures.
```

提案パッケージは `src/bytes`、`src/box`、`src/boxes`、`src/bitstream`、`src/demux`、`src/mux`、および `examples/demux`、`examples/fmp4`、`web/`、`native/`、`tools/oracle`、`tests/fixtures`。実際の `moon.pkg` 分割は [0002](./0002-moonbit-bootstrap.md) で循環依存・target 制約を検証した上で確定する。

### 変更できないデータ契約

1. `Sample.timestamp` は各 track の timescale 単位の **DTS**。PTS は `DTS + composition_time_offset`。CTTS 未設定(`None`)と 0 は区別する。DTS の全 track 時系列統合は float 丸めなしで比較する。
2. `Mp4FileDemuxer` と `Fmp4FileDemuxer` が返す sample `data_offset` は**ファイル絶対位置**。一方 `Fmp4SegmentDemuxer` が返す offset は**当該 media-segment buffer 先頭からの相対位置**。
3. `Mp4FileMuxer.append_sample` の入力 offset は**出力ファイル絶対位置**。`Fmp4SegmentMuxer.create_media_segment_metadata` の入力 offset は**当該 mdat payload 先頭からの相対位置**。後者の返り値に payload は含まれず、caller が連結する。
4. 通常 MP4 Demuxer の `RequiredInput` は `position` と `size: Option` 相当。上流の `handle_input` は要求された範囲を一度に満たす契約。固定長で分割受信した場合は I/O adapter で結合し、memory limit を超える要求は明示的に拒否する。
5. 初期の muxer は同一 `TrackKind` 1 トラックまで（映像／音声／字幕各 1）。多言語音声/字幕 mux を暗黙に支援しない。
6. JSON 比較では 64bit 整数を十進**文字列**で保持。JS の安全整数精度外を Number へ強制変換しない。
7. 不正入力による panic・制限なしの allocation・無限 loop を許容しない。parse 用 limits とエラーの位置/原因を持つ。正常入力と不完全入力は区別する。

### テスト・互換性判定

| 区分 | 入力/方法 | 判断 |
| --- | --- | --- |
| Unit | 手作りの合法/違法byte列、size境界、box親子関係、sample mapping | Whatが固定した結果／error種別に一致 |
| Upstream fixture | 上流`tests/testdata`の小さなMP4/AAC/Opus/AV1など（帰属確認後） | Rustの固定SHAから再生成したcanonical goldenと一致 |
| Rust differential | 同じfixtureからRust nativeまたはRust/WASMとMoonBitを別プロセスで動かす | Track kind/id、DTS/CTTS、offset/size、codec entry、失敗分類の一致 |
| Interop | Rust mux→MoonBit demux、MoonBit mux→Rust demux | encodeしたsample payload/metadataが完全復元できる |
| Fuzz/PBT | boundary mutation、壊れたbox、random seeds | panic/無限loop/範囲外参照をしない、発見seedを回帰化 |
| Browser E2E | 実ブラウザでFile input→tree/timeline表示→JSON export | 画像とデータの実操作証跡。差分Labは左右独立で実行 |
| Native UI E2E | Linuxを先行、Mac Apple Siliconは別途実機 | UI入力・選択・終了・表示の動作。未実機は未実行 |
| Performance | 同一fixtureとhostでelapsed/read count/retained memory | 数値の採取と回帰比較。未計測の高速化を宣言しない |

### 最初のデモ仕様：MP4 Inspector

- 左ペイン: box type/offset/size 階層。unknown box は RAW として示し、metadata を捏造しない。
- 中央: Video/Audio/Subtitle track、codec string、timescale、duration、sample 数。
- 右: sample index、DTS、PTS、keyframe、file offset、sample size、sample entry 切替。
- 入力: browser File API、ファイルを外部アップロードしない。Range 読取と解析 cancel を備える。
- 比較モード: Rust/WASM 結果と MoonBit 結果を左右並置し、異なる field path と値を表示する。
- 実演ケース: black-h264-video／beep-aac／black-av1／black-h264-fmp4／非faststart／切断・未知box。

M1 では**動画そのものの再生や変換**を UI に表示できなくてもよい。後続の [0029](./0029-webcodecs-transcode.md) だけが WebCodecs へ依存し、codec 未対応ブラウザは機能を無効化する。

### 進捗更新の規則

1. 個別 Issue の checkbox は**実際に実行した証拠がある項目だけ**完了にする。
2. PR には上流 SHA、予定/実装 API 差分、コマンド＋結果、fixture/CI link、既知 limitations を載せる。
3. M1 gate を満たしたら読み取り版を alpha 相当とし、その時点でまだ mux に手を付けていなくても意義ある成果としてデモを公開できる。
4. 完了時には Issue の記録を保持したまま `issues/closed` への移動を検討。未完了のものを移動しない。
5. イシューの追加・移動・状態変更・タイトル変更は、この index の該当行と同じ変更で更新する。
