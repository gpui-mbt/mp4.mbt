# 対象範囲と責務分離

この文書は mp4.mbt の互換性の意味・対象範囲・core と I/O の責務分離を固定する。
上流の固定参照と API 対応表は [`upstream.md`](./upstream.md) を参照。

## 1. 互換性の 3 層

互換性の主張は必ず次の 3 層のどれかを明示する。曖昧な「Rust 互換」は使わない。

| 層 | 対象 | 判定方法 | 適用範囲 |
| --- | --- | --- | --- |
| `wire` | 直列化された MP4 bytes | 該当箇所で byte 一致、または oracle の golden と一致 | box の再 encode、muxer 出力など明示した箇所だけ |
| `semantic` | track/sample、時刻、offset、失敗分類 | Rust oracle（[`../tools/oracle`](../tools/oracle)）の golden と観測値の一致 | M1 の基本判定。demuxer、kind detector、sample table |
| `surface` | MoonBit の公開 API 関数・型 | `moon info` の `.mbti` と対応表（`upstream.md` §3）のレビュー | 公開 API の追加・変更時 |

- M1（read-only）は `semantic` 一致を基本とする。`wire` 一致は decode→encode の往復テストなど、対象を限定して主張する。
- `wire` 一致を主張する再 encode は、デコード時のサイズ形式（size32 / largesize）を保つ wire-preserving を既定とし、最小幅へ畳む canonical 変換は別 API（`to_canonical` など）で明示する（Issue 0006）。
- 差分の観測値は JSON 正規化（64bit 整数は十進文字列）で比較し、フィールド単位で差分を追跡できるようにする（Issue 0004/0016）。
- Rust 側の実行失敗・candidate 側の実行失敗は「一致」ではない。未実行は Unverified として記録する（§6）。

## 2. バージョン境界

| バージョン | マイルストーン | 内容 | 未対応の扱い |
| --- | --- | --- | --- |
| v0.1 | M0–M1 | 通常 MP4 の read-only、box tree、track/sample、Native demux CLI、Web Dump、Rust 差分 Lab | mux・fMP4・コーデック意味解析は未対応と表示 |
| v0.2 | M2 | fMP4 の init/media segment 読み書き、fMP4 file demux、例 | 通常 MP4 の mux は未対応と表示 |
| v0.3 | M3 | 通常 MP4 の mux（faststart / 非 faststart） | Hybrid MP4 は未対応と表示 |
| v0.4 | M4 | AVC/HEVC/AAC/Opus/AV1/VPx 補助、字幕、Hybrid MP4 | decode/encode・WebCodecs は未対応と表示 |
| v0.5 | M5 | WebCodecs デモ、Native Inspector、fuzz/PBT、性能、公開文書、追従監査 | 未検証 target・未計測性能は Partial/Unverified と表示 |

- 各バージョンの機能はマイルストーン gate（Issue 0000 の表）を満たしてから「対応」と表示する。
- 「Implemented / Partial / Not started / Blocked」の表示規則は Issue 0033 で公開文書に反映する。本ドキュメントの §4 の表を一次情報とする。

## 3. 対象外（どのバージョンでも core に含めない）

- H.264/H.265/AV1 などのエンコーダー・デコーダー本体、動画再生、libwebrtc。
- C ABI の完全互換、上流 Rust クレートへの FFI ラッパー（「port」と称さない）。
- リアルタイム通信・ストリーミング配信基盤。
- ネットワークアクセスを core に含めること。ネットワークは利用者が収集した bytes を入力にする。
- M1 の Sample payload は raw bytes + offset としてのみ扱い、codec として解釈しない。

## 5. core と I/O の責務分離

```text
[Browser File.slice]  [Native file I/O]  [generated bytes]
        \                   |                  /
         +-------- Range I/O adapter --------+
                          |
             (bytes, position) / RequiredInput
                          |
        core: pure MP4 packages (no file/network/DOM)
        src/bytes, src/box, src/boxes, src/demux, src/mux, src/bitstream
                          |
        +-- Native CLI (examples/demux)     +-- Web Dump (web/)
        +-- Native Inspector (native/)      +-- Rust diff Lab (tools/)
```

- core の package はファイル・ネットワーク・DOM・時計・乱数へ依存しない。すべて (bytes, position) の入力と値/エラーの出力で完結する（Sans I/O）。
- 実ファイル I/O・HTTP Range・ブラウザ File API・とする UI は adapter 側に置き、core からは import しない。
- demuxer は `RequiredInput`（position, 要求サイズ）を返し、adapter が要求範囲を一度に満たす。固定長分割受信は adapter で結合する。memory limit を超える要求は明示的に拒否する。
- core は target 非依存（Native / JS で同じ値・同じエラー分類）であることをテストで固定する。UI 実装（Issue 0015/0030 など）は core の import のみを行い、core の挙動を分岐させない。

### 依存方向（循環禁止）

```text
bytes <- box <- boxes <- demux <- mux
  ^         ^        ^
  |         +--------+-- bitstream（boxes に sample entry 構築を提供）
  |                     （bitstream は bytes と boxes の公開型に依存）
  +-- 全 package が共有するエラー・カーソル・limits
```

- `bytes` は他の core package に依存しない。
- `demux` / `mux` は `boxes` までに依存し、互いには依存しない。
- 確定した package 分割・依存は Issue 0002 で検証して記録する。

## 6. データ契約（変更には全体レビューが必要）

1. `Sample.timestamp` は各 track の timescale 単位の **DTS**。PTS は `DTS + composition_time_offset`。CTTS 未設定（`None`）と 0 は区別する。DTS の全 track 時系列統合は float 丸めなしで比較する。
2. `Mp4FileDemuxer` / `Fmp4FileDemuxer` の `data_offset` は**ファイル絶対位置**。`Fmp4SegmentDemuxer` の offset は**当該 media-segment buffer 先頭からの相対位置**。
3. `Mp4FileMuxer.append_sample` の入力 offset は**出力ファイル絶対位置**。`Fmp4SegmentMuxer.create_media_segment_metadata` の入力 offset は**当該 mdat payload 先頭からの相対位置**。後者の返り値に payload は含まれず caller が連結する。
4. 通常 MP4 demuxer の `RequiredInput` は `position` と `size: Option`。要求範囲を一度に満たす契約とし、分割受信は adapter で結合する。memory limit 超の要求は明示的に拒否する。
5. 初期の muxer は同一 `TrackKind` 1 トラックまで（映像／音声／字幕各 1）。多言語音声・複数字幕の mux は暗黙に支援しない。
6. JSON 比較では 64bit 整数を十進**文字列**で保持し、JS の安全整数精度外を Number へ強制変換しない。
7. 不正入力による panic・制限なし allocation・無限 loop を許さない。parse 用 limits とエラーの位置/原因を持ち、正常入力と不完全入力を区別する。
8. box tree（`src/boxes` の `BoxNode`）の `start` / `payload_start` は入力バッファ先頭を 0 とする絶対位置（`ReadCursor` の base_offset を含む）。`mdat` はペイロードを保持せず `data_offset` / `data_size` の範囲だけで表す。入れ子の `size==0` は拒否し、深さ・ノード数は limits で制限する。

## 7. 検証状態の記録

検証状態は **PASS / FAIL / UNVERIFIED / NOT_RUN** を独立に記録する。「未実行」は PASS ではない。

- 記録にはコマンド・target・commit SHA・OS/arch・fixture checksum・日時を含める。
- Rust oracle が生成できない、candidate が起動しない場合も UNVERIFIED / NOT_RUN とする。
- golden は oracle 実行から生成し、手入力で「一致」を作らない。
- 機能表（§4）の状態は、対応する検証が PASS してから Implemented に変更する。
